پروژه نهایی React

این فصل سقف دوره است: همه‌ی مهارت‌هایی که از فصل ۱ تا ۴۹ یاد گرفتید را یک‌جا در یک پروژه‌ی واحد به کار می‌گیریم و هم‌زمان به مهم‌ترین «بهترین شیوه‌های» یک اپلیکیشن React واقعی اشاره می‌کنیم. پروژه‌مان یک داشبورد مدیریت وظایف تیمی است.

آنچه می‌سازیم

  • لیست وظایف با افزودن، ویرایش، حذف و جستجو (CRUD فصل ۴۹).
  • اعتبارسنجی فرم هنگام تایپ و هنگام submit (فصل ۲۳ و ۴۸).
  • ذخیره‌ی ماندگار در localStorage (فصل ۳۳).
  • همگام‌سازی با API و مدیریت Loading/Error (فصل ۳۱ و ۳۲).
  • تأیید حذف با حالت confirm (فصل ۴۹) و پیام‌های toast.

برنامه‌ی اپ

یک App با سه لایه‌ی منطق می‌سازیم: hook سفارشی برای داده، کامپوننت فرم، و کامپوننت لیست. داده‌ها متمرکز در بالاترین سطح نگه داشته می‌شوند و پایین‌تر فقط props دریافت می‌کنند:

App.jsx
import { useEffect, useState } from "react";

import TaskForm from "./TaskForm";

import TaskList from "./TaskList";

import { useTasks } from "./hooks/useTasks";



function App() {

  const [query, setQuery] = useState("");

  const { tasks, loading, error, add, update, remove } = useTasks();



  const filtered = tasks.filter((task) =>

    task.title.toLowerCase().includes(query.toLowerCase())

  );



  if (loading) return <p>در حال بارگذاری...</p>;

  if (error) return <p className="error">error</p>;



  return (

    <main>

      <h1>وظایف تیم</h1>

      <input

        placeholder="جستجو..."

        value={query}

        onChange={(e) => setQuery(e.target.value)}

      />

      <TaskForm onAdd={add} />

      <TaskList

        tasks={filtered}

        onUpdate={update}

        onRemove={remove}

      />

    </main>

  );

}

hook داده‌ها

تمام منطق داده در یک hook سفارشی ساکن است؛ کامپوننت‌ها هیچ‌گاه مستقیماً localStorage یا API را لمس نمی‌کنند. این همان جداسازی فصل ۱۷ و ۲۵ است:

hooks/useTasks.js
import { useEffect, useState } from "react";

import { fetchTasks, createTask, deleteTask } from "../api";



const KEY = "team-tasks";



export function useTasks() {

  const [tasks, setTasks] = useLocalStorage(KEY, []);

  const [loading, setLoading] = useState(false);

  const [error, setError] = useState(null);



  useEffect(() => {

    setLoading(true);

    fetchTasks()

      .then(setTasks)

      .catch(setError)

      .finally(() => setLoading(false));

  }, []);



  function add(title) {

    setTasks((prev) => [

      ...prev,

      { id: crypto.randomUUID(), title, done: false },

    ]);

  }



  function update(id, patch) {

    setTasks((prev) =>

      prev.map((task) =>

        task.id === id ? { ...task, ...patch } : task

      )

    );

  }



  function remove(id) {

    setTasks((prev) => prev.filter((task) => task.id !== id));

  }



  return { tasks, loading, error, add, update, remove };

}

فرم با Validation

فرمِ افزودن، همان الگوی فصل ۴۸ را دارد: state یکپارچه، خطا هنگام تایپ، و دکمه‌ی غیرفعال تا وقتی valid نشود:

TaskForm.jsx
import { useState } from "react";



function validateTitle(title) {

  if (!title.trim()) return "عنوان الزامی است";

  if (title.length < 3) return "حداقل ۳ کاراکتر";

  return null;

}



function TaskForm({ onAdd }) {

  const [title, setTitle] = useState("");

  const [error, setError] = useState(null);



  function handleSubmit(e) {

    e.preventDefault();

    const msg = validateTitle(title);

    if (msg) return setError(msg);

    onAdd(title.trim());

    setTitle("");

    setError(null);

  }



  return (

    <form onSubmit={handleSubmit}>

      <input

        value={title}

        onChange={(e) => {

          setTitle(e.target.value);

          setError(validateTitle(e.target.value));

        }}

        placeholder="عنوان وظیفه..."

      />

      <button disabled={validateTitle(title) !== null}>افزودن</button>

    </form>

  );

}

لیست و وضعیت‌ها

TaskList.jsx
import { useState } from "react";



function TaskList({ tasks, onUpdate, onRemove }) {

  const [confirmId, setConfirmId] = useState(null);



  if (tasks.length === 0)

    return <p>وظیفه‌ای نیست.</p>;



  return (

    <ul>

      {tasks.map((task) => (

        <li key={task.id}>

          <label>

            <input

              type="checkbox"

              checked={task.done}

              onChange={() => onUpdate(task.id, { done: !task.done })}

            />

            task.title

          </label>

          {confirmId === task.id ? (

            <span>

              حذف شود؟

              <button onClick={() => onRemove(task.id)}>بله</button>

              <button onClick={() => setConfirmId(null)}>خیر</button>

            </span>

          ) : (

            <button onClick={() => setConfirmId(task.id)}>حذف</button>

          )}

        </li>

      ))}

    </ul>

  );

}

بهترین شیوه‌ها در همین پروژه

  • هر کامپوننت فقط یک مسئولیت دارد و داده از بالا به پایین با props می‌آید.
  • تغییر state همیشه immutable است (spread و map، نه push مستقیم).
  • برای لیست‌ها key پایدار با crypto.randomUUID().
  • loading و error جدا از هم مدیریت می‌شوند تا کاربر وضعیت را بفهمد.
  • منطق داده در hook جدا است تا تستش با Jest/Testing Library آسان باشد (فصل ۴۴ و ۴۵).
  • فرم‌ها validation را هم هنگام تایپ و هم هنگام submit اجرا می‌کنند.
نکته: اگر پروژه بزرگ شود، این فقط شروع کار است: Context یا یک کتابخانه‌ی state (فصل ۲۵)، React Router (فصل ۲۷) برای چند صفحه، و Error Boundaries (فصل ۴۲) برای تاب‌آوری. همین الگو به تدریج به یک اپ کاملاً حرفه‌ای تبدیل می‌شود.

جمع‌بندی همینجا، و شروع سفر شما

دوره‌ی React تمام شد. شما حالا می‌توانید یک اپلیکیشن کامل با فرم، داده، ذخیره‌ی ماندگار، خطا و تعامل بسازید؛ چیزهایی که بسیاری از پروژه‌های واقعی روزمره همین‌ها هستند. از اینجا به بعد، تمرین کنید: پروژه‌ای واقعی برای خودتان انتخاب کنید و همین فصل آخر را دوباره و دوباره روی آن پیاده‌سازی کنید. موفق باشید!
